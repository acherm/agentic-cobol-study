# STORY — cobol-compress-codex (COBPACK)

## A compressor whose centre of gravity is verification hygiene

A COBOL compressor sounds like an algorithm exercise. The interesting thing about `cobol-compress-codex` is that it refused to become one. Codex (GPT-5.4, pragmatic profile, xhigh reasoning) shipped `cobpack` — a three-subcommand CLI over a self-designed columnar binary container — but the project's centre of gravity sits one layer above the codec. In the KEY_FEATURES ranking, the two top entries are tied at the top with identical scores, and they are both VER: a 48-case randomized round-trip suite and a 72-case typed-mutation fuzz suite. The RLESP codec, the thing the project is nominally about, ranks fourth. This is the only project in the COBOL corpus where the verification class wins on both score and count, and the phenomenon is not incidental — the fuzz suite caught a real SIGFPE in the agent's own COBOL (`reclen_zero` mutation dividing by an unvalidated record length) and the fix landed in the same session.

## Domain: fixed-record COBOL data, staged as MVP0 -> MVP1 -> TRUST

The brief was deliberately layered. MVP0 defined the CPC v0 container (8-byte `COBPACK\0` magic, uint32 version, uint32 record_len, uint64 record_count, uint32 field_count, then variable field descriptors, then columnar payloads) and required only a `NONE` codec — raw columnar transposition, exit codes 0 through 4, byte-identical round-trip including for 0-record inputs. MVP1 added a `RLESP` space-run codec (tag 0x00 literal, tag 0x01 space-run, `MIN_RUN=4`, `MAX_LIT=65535`), per-field `CODEC=` schema overrides, a CLI `--codec` flag, and AUTO selection for type-X fields only when RLESP actually shrinks the payload. The trust layer — determinism, randomized round-trip, corruption/fuzz, CRC32 oracle, all under a two-minute wall-clock budget — was requested last.

Pure COBOL is the load-bearing choice. GNUCobol has no pointers, no unions, no native little-endian helpers; `ORGANIZATION IS SEQUENTIAL` with `PIC X(1)` is how you get raw bytes, and `FUNCTION ORD`/`FUNCTION CHAR` are 1-based, which cost the agent a bug in turn 1. Writing a self-describing binary container under those constraints is domain modelling disguised as I/O, and the 1,493-line `cobpack.cob` plus 528-line `cobpack_schema.cob` are mostly the evidence of that choice, not of algorithmic work.

## Chronology: 12 user prompts, two sessions, zero clarifications

The engagement ran across two sessions, 2026-03-12 through 2026-03-23, with 12 user prompts in total; the three that did most of the specification work were spec-sized (PL-ROOT ~2000 words for MVP0, PL-002 ~800 words for MVP1, PL-003 ~50 words for the trust suite). None required clarification and none changed scope. Each turn followed the same rhythm: exhaustive user specification, a brief toolchain-research episode, a scaffold/implement pass, a debug cycle, green tests. Across 834 turns the agent logged 18 SB entries — 12 user-driven capabilities, 6 agent-initiated hardening fixes — and all six of the agent-initiated ones were triggered by observed test failures, never by speculative hardening.

## Delivered: 70-assertion trust stack on top of a modest codec

The shipped artefacts: the `cobpack` binary with `compress` / `decompress` / `info`; the CPC v0 container (MVP0) and its v1 extension (CRC32, MVP1); NONE and RLESP codecs with AUTO selection; a schema parser that synthesises `__GAP_nnnn` fields for uncovered record ranges so decompression is byte-identical without separate gap metadata; and a six-file test stack (`trust_lib.py`, `trust_determinism.py`, `trust_randomized.py`, `trust_fuzz.py`, `trust_crc32.py`, plus the shell harness) that together assert well over 70 properties in under 30 seconds. Determinism is not argued, it is proved: four witness cases are compressed five times each and the `.cpc` bytes, `info` output, and restored bytes must all be byte-identical across runs, with SHA-256 equality as the external oracle. Randomized round-trip covers 48 seeded cases that vary record length (1-64), record count (0-24), field count (1-6), gaps, types X and 9, codec overrides, and content modes (spaces, alpha, runs, random, digits); every case is compressed twice for determinism, decompressed, and CRC32-checked.

## The self-catching fuzz event

The fuzz suite is the narrative spine. `trust_fuzz.py` encodes a typed-mutation model over the CPC format — ten mutator classes: `magic`, `version`, `field_count_zero`, `reclen_zero`, `codec_invalid`, `payload_offset`, `payload_size`, `truncate`, `invalid_rlesp_tag`, `rlesp_mismatch` — plus 24 random garbage files, each run under a hard 2-second subprocess timeout. The contract is strict: no crash, no hang, no signal termination, and `decompress` must exit non-zero. On first run the `reclen_zero` mutator — which sets the container's `record_len` field to zero — crashed the COBOL binary with SIGFPE. The agent's own test machinery had just caught a divide-by-zero in the agent's own code. Root cause: `record_count = file_size / record_len` had no guard on `record_len = 0`. Fix landed in the same session, re-run was clean. Two siblings fell out of the same pass: the RLESP pending-space corruption bug (`rlesp-feed-byte` was overwriting a non-space byte while flushing a sub-MIN_RUN pending-space buffer, fixed by a saved-byte slot at `src/cobpack.cob:686-691`) and the synthetic-gap RLESP safety fix (gap fields are now force-pinned to `CODEC=NONE` because their contents are not guaranteed space-dominated).

The sequence — randomized generator finds the failure, typed mutator explains it, byte-level trace locates it, single-line COBOL fix closes it, full suite re-greens — is what the KEY_FEATURES ranking is reacting to when it puts two verification entries at the top.

## Compute and context profile

The engagement was lean. Across both sessions the agent consumed roughly 138,000 output tokens and ran about 1 hour 25 minutes of active wall-clock work. Peak context hit 202 k of the 258 k Codex window (78 %) and triggered 2 compactions. No network; sandbox was `workspace-write`; no packages installed. 12 user prompts to produce ~3,100 LOC of COBOL + Python, a documented trust claim, and a bug-hunting test suite is a low interaction-to-delivery ratio — especially given that three of those 12 carried the entire specification surface and the rest were mostly directional nudges between phases.

## Why the profile is unusual

Most agent-built MVPs of this size get as far as a green happy-path suite and stop. This one produced a suite designed to falsify itself, and the suite worked as intended: it found bugs the scripted tests had missed, and the agent treated those findings as first-class work, fixing them under the same budget. The KEY_FEATURES composition — VER 4, DOM 3, ALG 2, with VER also winning on score — is the quantitative shadow of that stance. It is the only project in the corpus where the agent's test machinery ranks above the code it is testing, and where the compressor ships with a written account (TRUST.md) of what a passing run does and does not prove. For a pure-COBOL MVP built in ~1 h 25 m of active time, that is a strikingly disciplined use of the compute budget.
